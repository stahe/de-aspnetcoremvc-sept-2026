    3. Das Action-Modell

    Eine Action benötigt Informationen, die der Browser sendet: die Parameter der URL ([?name=martin&age=42]), Formularfelder und Routenparameter. Der Quellkurs bezeichnet all diese Informationen als Action-Modell. Dieses Kapitel zeigt, wie [ASP.NET Core] diese Informationen an die Action übergibt, in den richtigen Typ konvertiert und validiert. Dieser Vorgang heißt Model Binding ([model binding]).

    using Microsoft.AspNetCore.Mvc;

namespace Example07.Controllers;

[Route("parameters")]
public class ParametersController : Controller
{
    // /parameters/action01?name=martin: der URL-Parameter [name] -> der Action-Parameter [name]
    [HttpGet("action01")]
    public string Action01(string? name)
    {
        return $"name = [{name}], of type {name?.GetType().Name ?? "null"}";
    }

    // /parameters/action02?age=42: der Wert wird in den Parametertyp KONVERTIERT
    [HttpGet("action02")]
    public string Action02(int age)
    {
        return $"age = [{age}], of type {age.GetType().Name}, ModelState.IsValid = {ModelState.IsValid}";
    }

    // /parameters/action03?age=42: int? unterscheidet einen fehlenden Parameter (null) von einer Null
    [HttpGet("action03")]
    public string Action03(int? age)
    {
        return $"age = [{age?.ToString() ?? "null"}], ModelState.IsValid = {ModelState.IsValid}";
    }

    // /parameters/action04?page=2: ein Standardwert, falls der Parameter fehlt
    [HttpGet("action04")]
    public string Action04(int page = 1)
    {
        return $"page = [{page}]";
    }

    // /parameters/action05?q=nest: [FromQuery(Name = ...)], wenn die Namen verschieden sind
    [HttpGet("action05")]
    public string Action05([FromQuery(Name = "q")] string? search)
    {
        return $"search = [{search}]";
    }

    // /parameters/action06?name=martin&age=42: alle Parameter auf einmal
    [HttpGet("action06")]
    public Dictionary<string, string> Action06()
    {
        return Request.Query.ToDictionary(p => p.Key, p => p.Value.ToString());
    }
}

    Gehen wir diesen Code durch:

    • Zeilen 10–12: Das Model Binding ordnet die Parameter der Action den Daten der Anfrage nach Namen zu: Der Parameter [name] der Action erhält den Wert des Parameters [name] aus der URL (dem Teil nach dem [?], der Query-String oder [query string] genannt wird). Der Typ [string?] zeigt an, dass der Wert fehlen kann; in diesem Fall ist er [null]. [name?.GetType().Name ?? "null"]: der Name des Werttyps oder die Zeichenkette ["null"] , wenn der Wert [null] ist (der Operator [??] liefert einen Ersatzwert);
    • Zeilen 17–19: Der Parameter ist als Typ [int] deklariert: Das Model Binding konvertiert die empfangene Zeichenkette (["42"]) in eine Zahl. Schlägt die Konvertierung fehl ([?age=abc]), wird die Action dennoch mit dem Standardwert des Typs ausgeführt (0 für einen [int]), und der Fehler wird in [ModelState] festgehalten; der Status des Model Bindings – [ModelState.IsValid] – wird dann zu [false];
    • Zeilen 24–26: Beim Typ [int?] (einer „nullable“ ganzen Zahl) wird ein fehlender Parameter als [null] dargestellt, nicht als 0: So lässt sich „kein Alter“ von „Alter 0“ unterscheiden;
    • Zeilen 31–33: Ein [C#] -Standardwert ersetzt einen fehlenden Parameter;
    • Zeilen 38–40: Das Attribut [[FromQuery(Name = "q")]] legt fest, wo der Wert zu suchen ist (in der URL) und unter welchem Namen: Der Parameter [search] der Action erhält den Parameter [q] aus der URL;
    • Zeilen 45–47: [Request.Query] bietet Zugriff auf alle URL-Parameter, ohne Zuordnung oder Konvertierung. [ToDictionary] ([LINQ]) erzeugt daraus ein Dictionary, das in JSON serialisiert wird.

    Die Anführungszeichen um die URL sind erforderlich, wenn sie das Zeichen [&] enthält, das für die Konsole eine besondere Bedeutung hat. Beachten Sie Folgendes:

    • Ein Parameter wird unabhängig von der Groß- und Kleinschreibung über seinen Namen gebunden ([?NAME=martin] ist ebenfalls gültig);
    • sein Wert wird konvertiert, und zwar in den deklarierten Typ. Das ist ein wichtiger Unterschied zu [NestJS], wo der Typ eines Parameters lediglich eine Deklaration war ([TypeScript]), die zur Kompilierzeit entfernt wurde;
    • Eine nicht mögliche Konvertierung verursacht keinen Fehler: Die Action wird mit einem Standardwert ausgeführt, und es ist Sache der Action, [ModelState.IsValid] zu prüfen. Ein „nullable“ Typ ([int?]) verhindert, dass ein fehlender oder ungültiger Wert mit 0 verwechselt wird.

    Akzentuierte Zeichen und Leerzeichen werden in einer URL codiert ([%C3%A9] für [é] usw.): [ASP.NET Core] decodiert sie vor dem Binding.

    using System.ComponentModel.DataAnnotations;

namespace Example08.Models;

// das Action-Modell: eine Klasse, deren Eigenschaften jeweils ihre Einschränkungen tragen
public class PersonModel
{
    [Required(ErrorMessage = "the name is required")]
    [StringLength(20, MinimumLength = 2, ErrorMessage = "the name must have 2 to 20 characters")]
    public string? Name { get; set; }

    [Required(ErrorMessage = "the age is required")]
    [Range(0, 150, ErrorMessage = "the age must be between 0 and 150")]
    public int? Age { get; set; }

    [Required(ErrorMessage = "the title is required")]
    [AllowedValues("Mr", "Mme", "Melle", ErrorMessage = "unknown title")]
    public string? Title { get; set; }

    // optional: kein [Required]
    [EmailAddress(ErrorMessage = "invalid email address")]
    public string? Email { get; set; }
}

    Kommentieren wir diesen Code:

    • Zeile 1: der Namespace der Validierungsattribute;
    • Zeile 10: Jeder erwartete Parameter ist eine öffentliche Eigenschaft ([{ get; set; }]: Sie kann gelesen und geschrieben werden). Das Model Binding erstellt ein [PersonModel]-Objekt und füllt dann jede Eigenschaft mit dem gleichnamigen Parameter;
    • Zeilen 8–9: Der Name ist erforderlich ([[Required]]) und muss zwischen 2 und 20 Zeichen lang sein ([[StringLength]]). Jedes Attribut akzeptiert eine benutzerdefinierte Fehlermeldung ([ErrorMessage]). Die Eigenschaften werden als „nullable“ deklariert ([string?], [int?]): Ein Parameter kann in einer Anfrage fehlen, und [[Required]] erzwingt diese Anforderung;
    • Zeilen 12–14: Das Alter wird in eine ganze Zahl konvertiert, die erforderlich ist und zwischen 0 und 150 liegen muss ([[Range]]);
    • Zeile 17: Die Anrede muss zu einer Liste von Werten gehören ([[AllowedValues]], eingeführt mit [.NET] 8);
    • Zeile 21: Die E-Mail-Adresse ist optional (kein [[Required]]); wenn sie angegeben wird, muss sie gültig sein.

    using System.Net;
using Example09.Models;
using Microsoft.AspNetCore.Mvc;

namespace Example09.Controllers;

// kein [ApiController]: die Action wird IMMER ausgeführt, und sie ist es, die
// entscheidet, was bei einem ungültigen Modell zu tun ist
[Route("persons")]
public class PersonsController : Controller
{
    [HttpGet("action01")]
    public ContentResult Action01(PersonModel person)
    {
        // ModelState: das Ergebnis des Bindings UND der Validierung des Modells
        if (ModelState.IsValid)
        {
            return Page($"<p>Welcome {person.Title} {person.Name} ({person.Age} years old)</p>");
        }
        // die Fehler, Feld für Feld
        var items = ModelState
            .Where(field => field.Value!.Errors.Count > 0)
            .Select(field => $"<li>{field.Key}: {string.Join(", ", field.Value!.Errors.Select(e => e.ErrorMessage))}</li>");
        return Page($"<p>The form contains errors:</p><ul>{string.Join("", items)}</ul>");
    }

    // eine HTML-Seite (in beiden Fällen Code 200)
    private ContentResult Page(string html) => Content(html, "text/html; charset=utf-8");
}

    Kommentieren wir diesen Code:

    • Zeile 9: Ohne [[ApiController]] wird die Action immer ausgeführt, unabhängig davon, ob das Modell gültig ist oder nicht. Ein Parameter vom Typ einer Klasse wird überall gesucht: in der URL, in den Formularfeldern und in der Route;
    • Zeile 13: Das Model Binding und die Validierung wurden vor der Ausführung der Action durchgeführt: Das Objekt [person] ist gefüllt, und [ModelState] enthält eventuelle Fehler;
    • Zeilen 16–18: keine Fehler: eine Willkommensseite;
    • Zeilen 21–23: andernfalls die Liste der Fehler. [ModelState] ist ein Dictionary, in dem jeder Schlüssel der Name eines Feldes ist ([Name], [Age] ...) und jeder Wert der Status dieses Feldes samt der Liste seiner Fehler ([Errors]). Die Methoden [LINQ], [Where] (filtern) und [Select] (transformieren) behalten die Felder mit Fehlern bei und erzeugen pro Feld eine HTML-Zeile. [!] teilt dem Compiler mit, dass ein Wert nicht [null] ist;
    • Zeile 24: eine Seite, die die Fehler auflistet;
    • Zeile 28: In beiden Fällen ist die Antwort eine HTML-Seite mit dem Statuscode 200.

    using System.ComponentModel.DataAnnotations;

namespace Example10.Models;

// IValidatableObject: eine in C# geschriebene Validierung für das, was die Attribute
// nicht ausdrücken können (hier: JEDES Element der Liste)
public class ChoiceModel : IValidatableObject
{
    private static readonly string[] Colors = ["red", "green", "blue"];

    [MinLength(1, ErrorMessage = "choose at least one color")]
    public List<string> Color { get; set; } = [];

    public IEnumerable<ValidationResult> Validate(ValidationContext context)
    {
        foreach (var color in Color.Where(c => !Colors.Contains(c)))
        {
            // yield return: die Methode gibt die Fehler einzeln zurück
            yield return new ValidationResult($"unknown color: {color}", [nameof(Color)]);
        }
    }
}

    Kommentieren wir diesen Code:

    • Zeile 7: Die Klasse implementiert die Schnittstelle [IValidatableObject]: eine in [C#] geschriebene Validierung für das, was die Attribute nicht ausdrücken können;
    • Zeile 11: [[MinLength(1)]]: Die Liste muss mindestens ein Element enthalten;
    • Zeilen 14–18: Die Methode [Validate], die von der Validierung nach den Attributen aufgerufen wird, prüft jede Farbe. Für jede unbekannte Farbe gibt sie einen Fehler ([ValidationResult]) zurück und gibt dabei das betroffene Feld an. [yield return] gibt die Fehler einzeln zurück, ohne eine Liste zu erstellen.

using Example11.Models;
using Microsoft.AspNetCore.Mvc;

namespace Example11.Controllers;

[Route("post")]
public class PostController : Controller
{

    [HttpPost("action01")]
    public object Action01()
    {
        return new
        {
            receivedType = Request.ContentType,

    // ein JSON-Body: [FromBody] deserialisiert ihn
    [HttpPost("action02")]

    [HttpPost("action03")]
    public string Action03([FromForm] string? name)
    {
        return $"name = [{name}]";

    // die Formularfelder, gebunden und validiert durch die Klasse PersonModel
    [HttpPost("action04")]
    public object Action04([FromForm] PersonModel person)
    {
        return new
        {
            person,
            valid = ModelState.IsValid,
            errors = ModelState.Values.SelectMany(v => v.Errors).Select(e => e.ErrorMessage),
        };
    }
}

    Ein Model Binder ist das Objekt, das den Wert eines Parameters aus der Anfrage erzeugt. [ASP.NET Core] stellt sie für alle gängigen Typen bereit; Sie können eigene schreiben. Die Datei [Binding/DateFrBinder.cs]:

    using System.Globalization;
using Microsoft.AspNetCore.Mvc.ModelBinding;

namespace Example12.Binding;

// ein "Model Binder": wandelt ein französisches Datum "23/09/2026" in ein DateOnly um
public class DateFrBinder : IModelBinder
{
    public Task BindModelAsync(ModelBindingContext context)
    {
        // der Rohwert aus der URL, dem Formular, der Route...
        var raw = context.ValueProvider.GetValue(context.ModelName).FirstValue;
        if (DateOnly.TryParseExact(raw, "dd/MM/yyyy", CultureInfo.InvariantCulture, DateTimeStyles.None, out var date))
        {
            // Erfolg: der Wert, den die Action erhält
            context.Result = ModelBindingResult.Success(date);
        }
        else
        {
            // Fehler: ein Fehler in ModelState ("31/02/2026" wird ebenfalls abgelehnt)
            context.ModelState.AddModelError(context.ModelName, $"[{raw}] is not a valid dd/mm/yyyy date");
        }
        return Task.CompletedTask;
    }
}
    • Zeile 7: Ein Model Binder implementiert die Schnittstelle [IModelBinder];
    • Zeile 9: Seine Methode [BindModelAsync] erhält den Binding-Kontext: den Parameternamen ([ModelName]), die Wertquellen ([ValueProvider]: die URL, das Formular, die Route ...), [ModelState] ...;
    • Zeile 12: der Rohwert des Parameters ([FirstValue]: der erste, falls es mehrere gibt);
    • Zeilen 13–16: [DateOnly.TryParseExact] konvertiert eine Zeichenkette im Format [dd/mm/yyyy] in [DateOnly] (ein Datum ohne Uhrzeit) und gibt [false] zurück, wenn das nicht möglich ist, auch bei einem nicht existierenden Datum (31/02/2026). Bei Erfolg liefert [ModelBindingResult.Success(date)] den Wert, den die Action erhält;
    • Zeile 21: Schlägt der Vorgang fehl, wird ein Fehler zu [ModelState] hinzugefügt;
    • Zeile 23: Die Methode ist ihrer Natur nach asynchron ([Task]), aber es gibt nichts abzuwarten: Sie gibt einen bereits abgeschlossenen Task zurück.

    using Microsoft.AspNetCore.Mvc.ModelBinding;

namespace Example12.Binding;

// die bevorzugte Sprache des Browsers, aus dem Header gelesen
// "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
public class LanguageBinder : IModelBinder
{
    public Task BindModelAsync(ModelBindingContext context)
    {
        var header = context.HttpContext.Request.Headers.AcceptLanguage.ToString();
        var first = header.Split(',')[0].Trim();
        var language = first.Length >= 2 ? first[..2].ToLowerInvariant() : "fr";
        context.Result = ModelBindingResult.Success(language);
        return Task.CompletedTask;
    }
}
    • Zeile 11: der Header [Accept-Language], der die bevorzugten Sprachen des Benutzers angibt;
    • Zeilen 12–13: die ersten beiden Buchstaben der ersten Sprache. [first[..2]] ist ein Bereich ([range]): die Zeichen mit den Indizes 0 und 1.

// ein selbst geschriebenes Validierungsattribut: [NoSpace]
public class NoSpaceAttribute : ValidationAttribute

    {
    }

    public override bool IsValid(object? value)

        // null wird akzeptiert: die Pflicht dazu ist Sache von [Required]
        return value is not string text || !text.Contains(' ');

    using Example12.Binding;
using Microsoft.AspNetCore.Mvc;

namespace Example12.Controllers;

[Route("examples")]
public class ExamplesController : Controller
{
    // /examples/schedule?day=23/09/2026: ein benutzerdefinierter Model Binder
    [HttpGet("schedule")]
    public IActionResult Schedule([ModelBinder(typeof(DateFrBinder))] DateOnly day)
    {
        if (!ModelState.IsValid)
        {
            return BadRequest(ModelState[nameof(day)]!.Errors[0].ErrorMessage);
        }
        return Ok($"schedule for the day [{day:yyyy-MM-dd}]");
    }

    // /examples/hello: ein Parameter, der nicht aus der URL, sondern aus einem Header stammt
    [HttpGet("hello")]
    public string Hello([ModelBinder(typeof(LanguageBinder))] string language)
    {
        return language == "en" ? "Hello!" : "Bonjour !";
    }

    // /examples/search?keyword=aspnet: ein benutzerdefiniertes Validierungsattribut
    [HttpGet("search")]
    public IActionResult Search([NoSpace] string? keyword)
    {
        if (!ModelState.IsValid)
        {
            return BadRequest(ModelState[nameof(keyword)]!.Errors[0].ErrorMessage);
        }
        return Ok($"search for [{keyword}]");
    }
}

    3.6.5. Fazit

    Das Action-Modell wird vom Model Binding anhand der Anfrage erstellt: Routenparameter, URL, Formularfelder, JSON-Body und Header. Die Werte werden in die Parametertypen konvertiert und dann anhand der Attribute validiert. Das Ergebnis dieser beiden Schritte wird in [ModelState] gespeichert. Bei einem JSON-Server lehnt [[ApiController]] ein ungültiges Modell automatisch ab; bei einer HTML-Anwendung prüft die Action selbst [ModelState.IsValid] (Beispiel 09), damit das Formular erneut angezeigt werden kann. Das ist das Thema des nächsten Kapitels.
