    2. Controller, Actions, Routing

    Dieses Kapitel untersucht den Weg, den eine Anfrage vom Browser bis zur Action nimmt, die sie verarbeitet, sowie die Antwort, die diese Action zurückgibt. Views werden erst in Kapitel 4 eingeführt: Hier geben Actions Text oder JSON direkt zurück.

    • Zeile 2: [WebApplication.CreateBuilder] erstellt den „Builder“ der Anwendung. Er liest die Konfiguration (die Datei [appsettings.json], Umgebungsvariablen usw.), richtet die Protokollierung ein und bereitet die Liste der Services der Anwendung vor, [builder.Services]. Der Parameter [args] enthält die Kommandozeilenargumente;
    • Zeile 5: Die Services, die [MVC] benötigt, um die Controller der Anwendung zu finden und ihre Actions auszuführen, werden der Liste hinzugefügt;
    • Zeile 8: Die Anwendung wird erstellt. Nach dieser Zeile kann die Liste der Services nicht mehr geändert werden;
    • Zeile 11: Die von den Controllern deklarierten Routen (die Attribute [[HttpGet]], [[Route]] ..., die wir noch besprechen werden) werden aktiviert: Ohne diese Zeile würde keine Action jemals aufgerufen;
    • Zeile 14: Startet den Webserver [Kestrel] und wartet auf Anfragen, bis die Anwendung beendet wird ([Ctrl-C]). Sofern nichts anderes angegeben ist, lauscht der Server auf Port 5000.

    Diese Datei enthält weder eine Klasse noch eine Methode namens [Main]: Es handelt sich um ein Programm mit Top-Level-Anweisungen. Der [C#]-Compiler verpackt diese Anweisungen selbst in eine Methode namens [Main], die als Einstiegspunkt des Programms dient. Beachten Sie auch das Fehlen von [using]-Direktiven: [WebApplication] gehört zum Namespace [Microsoft.AspNetCore.Builder], der automatisch importiert wird (siehe [ImplicitUsings] in der Einleitung).

    using Microsoft.AspNetCore.Mvc;

namespace Example01.Controllers;

// ein Controller ist eine Klasse, die von Controller erbt
public class HomeController : Controller
{
    // eine Action: die Methode, die für die Anfrage GET / aufgerufen wird
    [HttpGet("/")]
    public string Index()
    {
        // der von der Action zurückgegebene Wert ist die an den Browser gesendete Antwort
        return "Hello from ASP.NET Core MVC!";
    }
}
    • Zeile 1: der Namespace, der die Klasse [Controller] und die Attribute von [MVC] enthält;
    • Zeile 3: der Namespace für die Klassen dieser Datei. Üblicherweise enthält er den Projektnamen ([Example01]) und das Verzeichnis der Datei ([Controllers]). Die Form [namespace X;] (ohne geschweifte Klammern) gilt für die gesamte Datei;
    • Zeile 6: Ein Controller ist eine public-Klasse, die von der Klasse [Controller] erbt. Üblicherweise endet ihr Name auf [Controller]. [ASP.NET Core] findet die Controller der Anwendung automatisch – sie müssen nicht deklariert werden;
    • Zeile 9: Das Attribut [[HttpGet("/")]] ordnet die Methode [Index] den Anfragen [GET /] zu. Eine auf diese Weise einer Route zugeordnete Methode ist eine Action. Ein [C#]-Attribut wird in eckigen Klammern geschrieben, unmittelbar vor dem, was es beschreibt: Es fügt der Methode Informationen hinzu, die das Framework beim Start liest;
    • Zeile 13: Der von der Action zurückgegebene Wert ist die Antwort, die an den Browser gesendet wird.

    using Microsoft.AspNetCore.Mvc;

namespace Example02.Controllers;

public class HomeController : Controller
{
    // GET /: eine HTML-Seite mit Links zu den anderen Actions
    [HttpGet("/")]
    public ContentResult Index()
    {
        const string html = """
            <h2>Example 02 - routing</h2>
            <ul>
              <li><a href="/first">/first</a></li>
              <li><a href="/first/action01">/first/action01</a></li>
              <li><a href="/first/products/17">/first/products/17</a></li>
              <li><a href="/first/products/17/reviews/3">/first/products/17/reviews/3</a></li>
              <li><a href="/first/files/images/logo.png">/first/files/images/logo.png</a></li>
              <li><a href="/first/products/abc">/first/products/abc</a></li>
              <li><a href="/unknown">/unknown</a></li>
            </ul>
            """;
        // Content(text, type): eine Antwort, deren Typ wir selbst wählen (hier HTML)
        return Content(html, "text/html; charset=utf-8");
    }
}
    • Zeile 9: Die Action gibt nun keine Zeichenkette mehr zurück, sondern ein [ContentResult]: eine Antwort, deren Inhalt und Typ angegeben sind;
    • Zeilen 11–22: ein [C#]-Rohzeichenfolgenliteral [raw string literal], begrenzt durch drei Anführungszeichen. Es kann mehrere Zeilen umfassen und Anführungszeichen enthalten, ohne dass diese maskiert werden müssen. Leerzeichen vor dem schließenden ["""] werden aus jeder Zeile entfernt;
    • Zeile 24: Die Methode [Content(text, type)] der Klasse [Controller] erzeugt ein [ContentResult]. Der Typ [text/html] weist den Browser an, den Text als HTML zu interpretieren.

    Die Action [Index] liefert somit eine HTML-Seite, die Links zu den Actions des anderen Controllers enthält:

    using Microsoft.AspNetCore.Mvc;

namespace Example02.Controllers;

// Präfix, das alle Routen des Controllers gemeinsam haben
[Route("first")]
public class FirstController : Controller
{
    // GET /first
    [HttpGet("")]
    public string Index()
    {
        return "Action [Index] of the [First] controller";
    }

    // GET /first/action01
    [HttpGet("action01")]
    public string Action01()
    {
        return "Action [Action01] of the [First] controller, GET request";
    }

    // POST /first/action01: gleicher Pfad, andere HTTP-Methode
    [HttpPost("action01")]
    public string Action01Post()
    {
        return "Action [Action01Post] of the [First] controller, POST request";
    }

    // GET /first/products/17: {id} ist ein Routenparameter, ":int" eine Einschränkung
    [HttpGet("products/{id:int}")]
    public string Product(int id)
    {
        return $"Product no. {id}";
    }

    // GET /first/products/17/reviews/3: zwei Routenparameter
    [HttpGet("products/{id:int}/reviews/{number:int}")]
    public string Review(int id, int number)
    {
        return $"Review no. {number} of product no. {id}";
    }

    // GET /first/files/...: {**path} akzeptiert ein beliebiges Pfadende
    [HttpGet("files/{**path}")]
    public string File(string path)
    {
        return $"Requested file: {path}";
    }
}

    Gehen wir diesen Code durch:

    • Zeile 6: Das auf die Klasse angewendete Attribut [[Route("first")]] legt das allen Routen des Controllers gemeinsame Präfix fest: Seine Actions bearbeiten URL-Pfade, die mit [/first] beginnen;
    • Zeilen 10–11: [[HttpGet("")]]: Die Action [Index] bearbeitet [GET /first]. Die URL einer Action ist die Verkettung des Controller-Präfixes und des Action-Pfads;
    • Zeilen 17–18: Die Action [Action01] bearbeitet [GET /first/action01];
    • Zeilen 24–25: derselbe Pfad, aber für die Methode POST: [[HttpPost]] ersetzt [[HttpGet]]. Es gibt außerdem [[HttpPut]], [[HttpDelete]], [[HttpPatch]] ... Der Name der [C#] -Methode ([Action01Post]) ist beliebig: Für das Routing zählen nur die Attribute. Außerdem können innerhalb derselben Klasse zwei Methoden nicht denselben Namen mit denselben Parametern haben;
    • Zeilen 31–32: [{id}] ist ein Routenparameter: Dieses URL-Segment kann verschiedene Werte annehmen. [:int] ist eine Einschränkung: Das Segment muss eine ganze Zahl sein, andernfalls passt die Route nicht. Der Wert des Segments wird an den gleichnamigen Parameter der Action übergeben, [id], der bereits in [int] konvertiert wurde: Für [/first/products/17] ist [id] gleich der Zahl 17. Das ist das Model Binding ([model binding]), das das nächste Kapitel ausführlich behandelt;
    • Zeilen 38–39: zwei Routenparameter, die an zwei Parameter der Action übergeben werden;
    • Zeilen 44–46: [{**path}] ist ein „Catch-all“-Parameter ([catch-all]): Er akzeptiert jedes Ende einer URL, einschließlich [/].

    using Microsoft.AspNetCore.Mvc;

namespace Example03.Controllers;

[Route("responses")]
public class ResponsesController : Controller
{
    // ein String: unverändert gesendet, mit dem Typ [text/plain]
    [HttpGet("text")]
    public string Text()
    {
        return "<h1>Action [Text]</h1>";
    }

    // derselbe String, als HTML deklariert: der Browser interpretiert ihn
    [HttpGet("html")]
    public ContentResult Html()
    {
        return Content("<h1>Action [Html]</h1>", "text/html; charset=utf-8");
    }

    // ein Objekt: als JSON serialisiert, mit dem Typ [application/json]
    [HttpGet("json")]
    public object Json()
    {
        return new { lastName = "Martin", firstName = "Jean", age = 42 };
    }

    // ein Array: ebenfalls als JSON serialisiert
    [HttpGet("array")]
    public string[] Array()
    {
        return ["Mme", "Melle", "Mr"];
    }

    // IActionResult: die Action wählt die vollständige Antwort (Code, Inhalt)
    // StatusCode(201, ...): der Code 201 (Created) statt 200 (OK)
    [HttpGet("created")]
    public IActionResult ResourceCreated()
    {
        return StatusCode(201, new { message = "resource created" });
    }

    // keine Antwort: der Code 204 (No Content) bedeutet "nichts anzuzeigen"
    [HttpGet("empty")]
    public IActionResult EmptyResponse()
    {
        return NoContent();
    }

    // eine asynchrone Action: ASP.NET wartet auf das Ende der Aufgabe (Task)
    [HttpGet("task")]
    public async Task<object> AsyncTask()
    {
        var start = DateTime.Now;
        await Task.Delay(500); // eine Wartezeit von 500 ms, ohne den Server zu blockieren
        return new { wait = $"{(DateTime.Now - start).TotalMilliseconds:0} ms" };
    }

    // ein "erwarteter" Fehler: NotFound(...) erzeugt eine 404-Antwort
    [HttpGet("not-found")]
    public IActionResult NotFoundError()
    {
        return NotFound(new { message = "This resource does not exist" });
    }

    // ein "unerwarteter" Fehler: eine unbehandelte Ausnahme erzeugt eine 500-Antwort
    [HttpGet("exception")]
    public string Exception()
    {
        throw new InvalidOperationException("An unexpected error");
    }
}

    Gehen wir diesen Code durch:

    • Zeilen 9–12: Eine Zeichenkette wird unverändert gesendet, mit dem Header [Content-Type: text/plain; charset=utf-8];
    • Zeilen 16–19: dieselbe Zeichenkette, als HTML deklariert (siehe Beispiel 02): Der Browser interpretiert sie;
    • Zeilen 23–26: Ein Objekt wird als JSON serialisiert, mit dem Header [Content-Type: application/json]. [new { lastName = ..., firstName = ... }] erzeugt ein Objekt eines anonymen Typs: eines namenlosen, vom Compiler erzeugten Typs, der sich für Daten eignet, die nur einmal verwendet werden. Die Eigenschaftsnamen von JSON werden in „camelCase“ geschrieben (erster Buchstabe klein), nach der Konvention von [JavaScript];
    • Zeilen 30–33: Auch ein Array wird als JSON serialisiert. [["Mme", "Melle", "Mr"]] ist ein Collection-Ausdruck ([C#] 12), der hier ein Array von Zeichenketten erzeugt;
    • Zeilen 39–41: Wenn die Action den Statuscode selbst festlegen muss, gibt sie ein [IActionResult] zurück: ein Objekt, das die vollständige Antwort beschreibt. Die Methoden der Klasse [Controller] erzeugen viele davon: [StatusCode(201, object)] erzeugt eine Antwort mit dem Code 201 ([Created]), deren Inhalt das in JSON serialisierte Objekt ist;
    • Zeilen 46–48: [NoContent()] gibt den Statuscode 204 zurück ([No Content]): „kein Inhalt“;
    • Zeilen 53–57: Eine Action kann asynchron ([async]) sein: Sie gibt dann einen Task zurück ([Task<T>]), das Äquivalent eines Promise ([JavaScript]), und [ASP.NET Core] wartet, bis der Task abgeschlossen ist, bevor es antwortet. [await Task.Delay(500)] wartet 500 ms, ohne den Server zu blockieren: Während des Wartens wird der Thread, der die Action ausgeführt hat, an den Server zurückgegeben, der ihn für die Bearbeitung anderer Anfragen nutzen kann. So werden alle Actions geschrieben, die eine Datenbank abfragen;
    • Zeilen 62–64: Ein vom Programm erwarteter Fehler: [NotFound(object)] gibt eine 404-Antwort mit JSON-Inhalt zurück. Entsprechend gibt es [BadRequest(...)] (400), [Unauthorized()] (401), [Forbid()] (403), [Ok(...)] (200) ...;
    • Zeilen 69–71: ein unerwarteter Fehler: Die Action löst eine Ausnahme aus, die sie nicht behandelt. [ASP.NET Core] antwortet dann mit einem Fehler 500 ([Internal Server Error]).

    using Microsoft.AspNetCore.Mvc;

namespace Example04.Controllers;

public class RedirectsController : Controller
{
    // permanente Weiterleitung (301): die Seite hat dauerhaft eine neue Adresse
    [HttpGet("old")]
    public IActionResult OldPage()
    {
        return RedirectPermanent("/new");
    }

    [HttpGet("new")]
    public string NewPage()
    {
        return "You are on the [new] page";
    }

    // temporäre Weiterleitung (302) auf eine berechnete Adresse
    [HttpGet("go/{destination}")]
    public IActionResult Go(string destination)
    {
        return Redirect($"/page/{destination}");
    }

    // Weiterleitung auf eine ACTION: ASP.NET erstellt die URL selbst
    [HttpGet("to-action/{destination}")]
    public IActionResult ToAction(string destination)
    {
        return RedirectToAction(nameof(Page), new { name = destination });
    }

    [HttpGet("page/{name}")]
    public string Page(string name)
    {
        return $"You are on the [{name}] page";
    }

    // Weiterleitung auf eine andere Website
    [HttpGet("documentation")]
    public IActionResult Documentation()
    {
        return Redirect("https://learn.microsoft.com/aspnet/core");
    }
}

    Gehen wir diesen Code durch:

    • Zeilen 9–11: [RedirectPermanent(url)] erzeugt eine dauerhafte Weiterleitung (Statuscode 301, [Moved Permanently]): Die Adresse der Seite hat sich dauerhaft geändert. Browser und Suchmaschinen können die neue Adresse zwischenspeichern;
    • Zeilen 22–24: [Redirect(url)] erzeugt eine vorübergehende Weiterleitung (Statuscode 302, [Found]), hier an eine berechnete Adresse. [$"/page/{destination}"] ist eine interpolierte Zeichenkette: Der Ausdruck in den geschweiften Klammern wird durch seinen Wert ersetzt;
    • Zeilen 29–31: [RedirectToAction(action, values)] leitet an eine Action weiter, nicht an eine URL: [ASP.NET Core] erzeugt die URL der Action [Page] selbst anhand ihrer Route ([page/{name}]) und der übergebenen Werte ([name = destination]). Wenn sich der Pfad der Action jemals ändert, folgt die Weiterleitung automatisch. [nameof(Page)] gibt den Methodennamen zurück (["Page"]): Ein Tippfehler würde einen Kompilierungsfehler verursachen, was bei einer von Hand geschriebenen Zeichenkette nicht der Fall ist;
    • Zeilen 42–44: Sie können auf eine andere Website weiterleiten.

    2.5. Beispiel 05: Die Objekte Request und Response

    Jede Anfrage wird durch ein [HttpContext]-Objekt dargestellt, das die Anfrage ([Request]) und die gerade erzeugte Antwort ([Response]) enthält. Eine Action greift direkt über die Eigenschaften [HttpContext], [Request] und [Response] der Klasse [Controller] darauf zu. Das ist manchmal notwendig, und wir tun es in der Fallstudie (zum Beispiel, um ein Cookie zu lesen oder zu setzen), aber man muss wissen, was man tut.

    using Microsoft.AspNetCore.Mvc;

namespace Example05.Controllers;

[Route("http")]
public class HttpController : Controller
{
    // die Anfrage: Methode, Pfad, Parameter, Header...
    [HttpGet("request")]
    public object RequestInfo()
    {
        return new
        {
            method = Request.Method,
            path = Request.Path.Value,
            parameters = Request.QueryString.Value,
            browser = Request.Headers.UserAgent.ToString(),
            ip = HttpContext.Connection.RemoteIpAddress?.ToString(),
        };
    }

    // die Antwort: wir fügen ihr einen Header hinzu, dann gibt die Action ihren Wert ganz normal zurück
    [HttpGet("header")]
    public string Header()
    {
        Response.Headers["X-Example"] = "05-httpcontext";
        return "Response with an added header";
    }

    // die Antwort "von Hand" geschrieben: Code, Typ, dann der Body
    [HttpGet("response")]
    public async Task ResponseByHand()
    {
        Response.StatusCode = 200;
        Response.ContentType = "text/plain; charset=utf-8";
        await Response.WriteAsync("Response written by [Response.WriteAsync]");
    }

    // FEHLER, den man nicht machen darf: die Antwort schreiben und DANN ein Ergebnis zurückgeben
    [HttpGet("double")]
    public async Task<IActionResult> Double()
    {
        await Response.WriteAsync("Start of the response... ");
        // die Antwort ist bereits raus: ihr Code und ihre Header können sich nicht mehr ändern
        return NotFound();
    }
}

    Gehen wir diesen Code durch:

    • Zeilen 10–18: die Anfrage: die HTTP-Methode ([Request.Method]), der Pfad ([Request.Path]), die URL-Parameter ([Request.QueryString]), die Header ([Request.Headers]) und, über [HttpContext.Connection], die Adresse (IP) des Clients. [?.] ist der „Null-conditional“-Operator: Wenn [RemoteIpAddress] gleich [null] ist, ergibt der Ausdruck [null] , statt einen Fehler zu verursachen;
    • Zeilen 24–27: Die Action fügt der Antwort einen Header hinzu und gibt dann ganz normal ihren Wert zurück, den [ASP.NET Core] sendet. Das ist die häufigste Verwendung von [Response];
    • Zeilen 32–36: Die Action schreibt die Antwort selbst – Statuscode, Typ, dann den Body – mit [Response.WriteAsync]. Sie gibt nichts zurück ([Task], nicht [Task<T>]);
    • Zeilen 41–45: der zu vermeidende Fehler: einen Teil der Antwort zu schreiben und dann ein Ergebnis zurückzugeben. Sobald die ersten Bytes des Bodys an den Browser gesendet wurden, können der Statuscode und die Header – die vor dem Body gesendet wurden – nicht mehr geändert werden.

    using Microsoft.AspNetCore.Mvc;

namespace Example06.Products;

[Route("products")]
public class ProductsController : Controller
{
    private readonly IProductsService productsService;

    // Dependency Injection: ASP.NET stellt die Implementierung von IProductsService bereit
    public ProductsController(IProductsService productsService)
    {
        this.productsService = productsService;
    }

    [HttpGet("")]
    public IReadOnlyList<Product> List()
    {
        return productsService.FindAll();
    }

    [HttpGet("{id:int}")]
    public IActionResult OneProduct(int id)
    {
        var product = productsService.FindById(id);
        if (product is null)
        {
            return NotFound(new { message = $"Product no. {id} not found" });
        }
        return Ok(product);
    }
}
    • Zeilen 11–13: Dependency Injection. Der Controller deklariert in seinem Konstruktor, dass er einen [IProductsService] benötigt; [ASP.NET Core] stellt ihm das für diesen Typ registrierte Objekt bereit (siehe unten). Der Controller ruft niemals [new ProductsService()] auf: Er kennt diese Klasse nicht einmal, nur die Schnittstelle. Die Implementierung könnte ersetzt werden (durch eine Version, die eine Datenbank liest, oder durch eine Testversion), ohne den Controller zu ändern;
    • Zeilen 17–19: Die Action delegiert an den Service. Die Liste wird mit JSON serialisiert;
    • Zeilen 23–30: [{id:int}] konvertiert die Kennung; für ein nicht vorhandenes Produkt wird eine 404-Antwort zurückgegeben. [Ok(object)] gibt eine 200-Antwort zurück, deren Inhalt das in JSON serialisierte Objekt ist. [is null] prüft, ob ein Wert null ist.

    2.6.6. Registrierung der Services

    [ASP.NET Core] kann einen Service nur bereitstellen, wenn es ihn kennt: Jeder Service wird registriert in [builder.Services], zusammen mit seiner Lebensdauer. Die Datei [Products/ProductsExtensions.cs]:

    namespace Example06.Products;

// eine "Erweiterungsmethode": sie wird aufgerufen, als gehörte sie zu
// IServiceCollection (builder.Services.AddProducts()). Sie bündelt die
// Registrierungen des Teils "Produkte" der Anwendung.
public static class ProductsExtensions
{
    public static IServiceCollection AddProducts(this IServiceCollection services)
    {
        // "wenn ein IProductsService angefordert wird, einen ProductsService liefern";
        // Singleton: eine einzige Instanz, von allen Anfragen gemeinsam genutzt
        services.AddSingleton<IProductsService, ProductsService>();
        return services;
    }
}
    • Zeile 6: eine statische Klasse, die nur statische Methoden enthält;
    • Zeile 8: eine Erweiterungsmethode. Das Schlüsselwort [this] vor dem ersten Parameter erlaubt es, sie aufzurufen, als gehörte sie zum Typ dieses Parameters: [builder.Services.AddProducts()]. So fügen die Bibliotheken von [ASP.NET Core] ihre Services hinzu ([AddControllers], [AddAuthentication] ...), und es ist eine gute Möglichkeit, die Registrierungen eines bestimmten Anwendungsteils zusammenzufassen;
    • Zeile 12: „Wenn eine Klasse einen [IProductsService] anfordert, stelle ihr einen [ProductsService] bereit.“ [Singleton] ist die Lebensdauer des Services: eine einzige Instanz, die bei der ersten Anfrage erstellt und von allen Anfragen gemeinsam genutzt wird. Es gibt zwei weitere Lebensdauern: [Scoped] (eine Instanz pro Anfrage) und [Transient] (eine neue Instanz bei jeder Anforderung). Kapitel 6 kommt auf dieses Thema zurück;
    • Zeile 13: Die Methode gibt die Liste der Services zurück, damit Aufrufe verkettet werden können.
