    Dieses Dokument ist ein Produkt der KI Claude von Anthropic. Es knüpft an das Dokument „Schritt-für-Schritt-Einführung in das Web-Framework [NestJS]“ (2026) an, das seinerseits das Dokument „Einführung in ASP.NET MVC anhand von Beispielen“ (2013) an das Framework [NestJS] angepasst hat. Dieses Dokument geht den umgekehrten Weg und kehrt zur Plattform [.NET] in ihrer aktuellen Version zurück:

    • das Framework [NestJS] und die Sprache [TypeScript] werden durch das Framework [ASP.NET Core MVC] und die Sprache [C#] ersetzt;
    • die [Handlebars]-Views werden durch [Razor]-Views ersetzt;
    • ORM und [TypeORM] werden durch ORM und [Entity Framework Core] ersetzt, weiterhin auf Basis von [MySQL].

    Das Dokument folgt eng dem Aufbau des Kurses zu [NestJS]: zunächst zahlreiche kleine Projekte, die jeweils ein einzelnes Konzept behandeln, danach eine umfassende Fallstudie – eine Webanwendung zur Terminplanung für eine Arztpraxis – mit vollständig kommentierten Dateien. Die Beispiele tragen dieselben Nummern und behandeln dieselben Themen wie im Kurs zu [NestJS]: Wer diesen Kurs kennt, kann die beiden Frameworks Beispiel für Beispiel vergleichen. Das ist jedoch nicht nötig: Dieses Dokument ist in sich abgeschlossen und setzt keine Vorkenntnisse in [NestJS] und auch nicht in [ASP.NET] voraus. Die einzigen Voraussetzungen sind Grundkenntnisse der Webprogrammierung (das HTTP-Protokoll, die Sprache HTML) und die Sprache [C#].

    1.1. Die Rolle von ASP.NET Core MVC in einer Webanwendung

    Eine Webanwendung ist oft in Schichten aufgebaut, wobei jede Schicht nur mit ihren Nachbarschichten kommuniziert:

    • Die Web-Schicht empfängt HTTP-Anfragen vom Browser und liefert ihm HTML-Seiten zurück. Bei dieser Schicht hilft uns [ASP.NET Core MVC] beim Schreiben;
    • Die Geschäftsschicht enthält die Geschäftsregeln der Anwendung (zum Beispiel „ein Patient kann nur einen bevorstehenden Termin haben“). Sie weiß nichts vom Web: Sie könnte genauso gut eine Kommandozeilenanwendung bedienen;
    • Die Datenzugriffsschicht (DAO-Schicht, [DAO] für [Data Access Object]) liest aus der Datenbank und schreibt in sie. Wir verwenden den ORM [Entity Framework Core] ([Object Relational Mapper]), der die Zeilen der Tabellen auf Objekte in [C#] abbildet.

    Die Web-Schicht selbst folgt dem Modell [MVC] ([Model – View – Controller]):

    • Der Controller (C) ist eine Klasse, deren Methoden – Actions genannt – jeweils einen bestimmten Anfragetyp bearbeiten (zum Beispiel [GET /schedule]). Eine Action liest die Anfrageparameter, ruft die Geschäftsschicht auf und wählt anschließend die anzuzeigende View aus;
    • Das Modell (M) ist die Menge der Daten, die die Action an die View übergibt: ein [C#]-Objekt;
    • Die View (V) ist eine [Razor]-Datei (Erweiterung [.cshtml]): ausgehend von HTML, in dem [C#]-Ausdrücke – eingeleitet durch das Zeichen [@] – durch Daten aus dem Modell ersetzt werden.

    Die Verarbeitung einer Anfrage folgt den nummerierten Schritten im Diagramm:

    • 1: Der Browser sendet eine HTTP-Anfrage, zum Beispiel [GET /schedule?doctorId=1&day=2026-09-24];
    • 2: Der Webserver [Kestrel], in [ASP.NET Core] integriert, empfängt die Anfrage. Sie durchläuft eine Reihe von Middleware-Komponenten (Lesen von Cookies, Authentifizierung, statische Dateien usw.), anschließend wählt [ASP.NET Core] die Action aus, die für diese Anfrage zuständig ist: Das ist das Routing. Bevor die Anfrage die Action erreicht, kann sie noch Filter durchlaufen, die wir in späteren Kapiteln untersuchen;
    • 3: Die Action fordert die benötigten Daten von der Geschäftsschicht an;
    • 4: Sie erstellt das Modell der View und bestimmt die View, die es anzeigen soll;
    • 5: Die [Razor]-View-Engine erzeugt die HTML-Seite, die [ASP.NET Core] an den Browser zurückgibt.

    [ASP.NET Core] ist das Web-Framework der Plattform [.NET] von Microsoft. Es ist kostenlos und quelloffen und läuft unter [Windows], [Linux] und [macOS]. Es kann Server erstellen, die JSON an einen [JavaScript]-Client ([Angular], [React], [Flutter] ...) liefern, ebenso wie klassische Webanwendungen, bei denen der Server die HTML-Seiten erzeugt und der Browser sie lediglich anzeigt. Dieser zweite Anwendungsfall – der MVC-Teil des Frameworks – wird in diesem Dokument behandelt. Wie [NestJS], das sich stark daran orientiert hat, beruht [ASP.NET Core] auf zwei Ideen: Attribute ([[HttpGet]], [[Route]], [[Authorize]] ...) beschreiben die Aufgaben von Klassen und Methoden, und Dependency Injection versorgt jedes Objekt mit den Abhängigkeiten, die es benötigt.

    1.2. Verwendete Werkzeuge

    Die Beispiele wurden mit den folgenden Werkzeugen geschrieben und getestet (ihre Installation wird im Anhang beschrieben):

    • das [.NET]-10-SDK ([Software Development Kit]), das den [C#]-Compiler, das Framework [ASP.NET Core] und das Kommandozeilenwerkzeug [dotnet] enthält. [.NET] 10 ist die aktuelle LTS-Version (Long-Term Support);
    • der Editor [Visual Studio Code] mit der Erweiterung [C# Dev Kit];
    • ein aktueller Browser ([Chrome], [Firefox], [Edge]);
    • das Kommandozeilenwerkzeug [curl], das die rohen HTTP-Antworten anzeigt (es ist in [Windows] 10 und 11 enthalten);
    • das DBMS [MySQL] (oder [MariaDB]), zum Beispiel das von [Laragon] unter [Windows], ab dem Kapitel zum Datenzugriff und für die Fallstudie.

    Das Framework [ASP.NET Core] ist Teil des SDK: Die Beispiele benötigen bis Kapitel 8 keine zusätzlichen Bibliotheken. Die Beispiele 25 bis 28 und die Fallstudie verwenden drei Bibliotheken, die bei der ersten Kompilierung automatisch von der Website [nuget.org] heruntergeladen werden (Sie müssen an diesem Tag also mit dem Internet verbunden sein): [Microsoft.AspNetCore.Authentication.JwtBearer] (JWT-Token), [BCrypt.Net-Next] (Passwort-Hashes) und [Pomelo.EntityFrameworkCore.MySql] ([Entity Framework Core] für [MySQL]).

    1.3. Die Fallstudie ausführen

    Anmerkung des Rezensenten: Ich rate dem Leser, die Fallstudie sofort wie unten beschrieben durchzuführen. Sobald Sie die Rolle dieser Terminplanungsanwendung vollständig verstanden haben, bitten Sie Ihre bevorzugte KI, die Anwendung wie folgt zu ändern: Ab sofort kann jeder Arzt:

    • seine eigenen Terminslots zwischen zwei Daten festlegen. So kann er seinen Terminkalender nach Bedarf anpassen;
    • bestimmte Zeitslots für einen bestimmten Tag aus dem Kalender entfernen – zum Beispiel, wenn er aus persönlichen Gründen nicht verfügbar ist;

    Die Änderung ist nicht trivial, da sie eine Änderung der Datenbankstruktur erfordert. Bitten Sie die KI, Ihnen den neuen Anwendungscode und das SQL-Skript zur Erstellung der neuen Datenbank zu liefern. Dazu müssen Sie ihr die ZIP-Datei mit dem vollständigen Projekt sowie das SQL-Skript der alten Datenbank zur Verfügung stellen.

    Außerdem habe ich den von Claude erstellten Kurs nicht durchgesehen. Er hatte bereits einen perfekten [NestJS]-Kurs erstellt. Ich bin davon ausgegangen, dass das auch hier der Fall ist. Wenn Sie etwas nicht verstehen, ist die Lösung immer dieselbe: Bitten Sie Ihre bevorzugte KI, Ihnen zu erklären, was Sie nicht verstehen. Claude zum Beispiel ist darin sehr gut.
